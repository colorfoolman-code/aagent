appendix A  Setting up the sample code repository

The companion repository for this book hosts the sample code that accompanies the chapters. It demonstrates how to build and run an AI agent using OpenAI’s tools and APIs, and it is organized so that each chapter’s examples live in a separate folder. Before you can work through the listings in the chapters, you need a working copy of the repository on your machine, a Python environment that matches what the samples expect, and a valid OpenAI API key connected through a local environment file.

This appendix walks through that setup end to end. It is organized into four sections that follow the natural setup order: cloning the repository, creating a Python environment, installing the dependencies and configuring your API key, and finally running one of the sample agents to confirm that everything is wired up correctly. Follow the sections in order the first time through; on subsequent visits, you can skip ahead to whichever step you need.

A.1 Cloning the repository

To get started, clone the repository to your local machine. The repository is hosted on GitHub and can be retrieved with a standard git clone command. Open a terminal, change to the directory where you keep your projects, and run the following commands:

git clone https://github.com/cxbxmxcx/AI-Agent-Workflows.git
cd AI-Agent-Workflows

The first command downloads a full copy of the repository into a new AI-Agent-­Workflows folder. The second command moves you into that folder so that the remaining setup steps run in the right place.

A.2 Creating a Python environment

The project requires Python 3.11 or later. The recommended approach is to create a dedicated virtual environment for the repository so that its dependencies do not interfere with other Python projects on your machine. The exact commands depend on your operating system, so the following paragraphs split the instructions for Windows and macOS or Linux.

On Windows, from a command prompt or PowerShell window in the repository root, run

python -m venv venv
venv\Scripts\activate

On macOS or Linux, from a terminal in the repository root, run

python3 -m venv venv
source venv/bin/activate

On either platform, once the environment is activated, your shell prompt is prefixed with (venv), which confirms that subsequent python and pip commands run inside the virtual environment.

If you prefer to use an existing Python installation instead of the virtual environment created earlier, you can point VS Code to that interpreter. To do so, follow these steps:

  1. Open the Command Palette by pressing Ctrl-Shift-P on Windows or Linux, or Cmd-Shift-P on macOS.
  2. Search for Python: Select Interpreter.
  3. Choose the Python interpreter you want to use for this project.

A.3 Installing dependencies and configuring the environment

With a working Python environment in place, the next step is to install the packages the samples depend on and give them access to your OpenAI API key. The repository pins its dependencies in a requirements.txt file at the repository root and reads your API key from a local .env file. This section covers the two installation paths and the API key configuration in turn.

A.3.1 Path A: Using the VS Code debugger

If you have VS Code installed with the Python extension, you can press F5 to start debugging one of the sample files. The launch configuration shipped with the repository ensures that the required dependencies are installed automatically before the sample runs. This is the fastest path if you do not want to manage dependencies by hand.

A.3.2 Path B: Installing manually with pip

If you prefer to install the dependencies yourself, or if you are running the samples from a plain terminal, run the following command from the repository root with your virtual environment activated:

pip install -r requirements.txt

pip downloads each pinned package and installs it into the active virtual environment. Depending on your network connection, this can take a minute or two the first time.

A.3.3 Configuring the OpenAI API key

The samples authenticate to OpenAI using an API key read from an .env file in the repository root. The repository includes an .env.example file that you can copy as a starting point. Create a new file named .env in the repository root with the following contents:

OPENAI_API_KEY=your_openai_api_key_here

Replace your_openai_api_key_here with your actual OpenAI API key. You can obtain a key from the OpenAI API Keys page at https://platform.openai.com/account/api-keys.

WARNING Never share or commit your .env file to version control. It contains a secret credential that grants access to your OpenAI account, and anyone who obtains it can incur charges to your account.

A.4 Running the sample code

With the repository cloned, the virtual environment active, the dependencies installed, and your API key in place, you are ready to run one of the samples. This section shows you how to run a sample, deal with the most common problems you might encounter, and adopt a few small habits that will keep your setup healthy over the course of the book.

A.4.1 Running a sample

Each chapter’s code lives in its own folder under the repository root. To run a sample, navigate to the chapter folder and execute the Python file. For example, to run the first agent from chapter 2:

python chapter_02/01_first_agent.py

The agent runs to completion and prints its output to the terminal. You can follow the same pattern for any other sample in the repository by replacing the path with the chapter and file you want to run.

A.4.2 Troubleshooting common problems

Most setup problems come down to one of two root causes: a missing or incorrect API key, or the wrong active Python interpreter. The following two patterns cover almost everything you are likely to see:

  • If you see an authentication error, double-check that your .env file is in the repository root and that OPENAI_API_KEY is set to a valid key.
  • If you see a ModuleNotFoundError, confirm that your virtual environment is active and that the dependencies were installed against it.

A.4.3 Keeping your setup healthy

A few small habits will save you time as you work through the rest of the book:

  • Make sure the Python interpreter you are using actually matches the environment you set up. Mixing system Python with a project virtual environment is the most common cause of import errors.
  • The .env file is listed in .gitignore and should never be committed to version control. Keep it local to your machine to keep your API key secure.
  • If you rotate your OpenAI API key for any reason, update the value in .env before running the samples again.
